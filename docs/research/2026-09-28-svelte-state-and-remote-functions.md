Svelte state, remote functions and the modern JavaScript baseline

Observed 2026-09-28. Research for Wayfinder ticket [#43](https://github.com/layerdbiz/tridentcubed/issues/43), feeding [#7](https://github.com/layerdbiz/tridentcubed/issues/7), where decisions stay. Sources: svelte.dev docs and blog, maintainers' GitHub proposals, Svelte Society talk pages, vite.dev and esbuild docs, `sveltejs/kit` source. No secondary write-ups. Trident: `svelte@5.50.0`, `@sveltejs/kit@2.50.2`, `vite@7.3.1` (`pnpm-lock.yaml`), both experimental flags on in `apps/app/svelte.config.js`, no `build.target` set.

## Short answer

1. **State**: shared reactive state takes one of two documented shapes, a `$state` object that is only mutated, or private `$state` behind getter/setter functions; reassigned `$state` cannot be exported. Per-instance state is a class with `$state` fields. State that SSR can touch goes in context, not module scope. Stores are "no longer necessary" but not deprecated. Trident's `mq.svelte.ts` and its rune classes already match.
2. **Remote functions**: `query`, `query.batch`, `query.live`, `form`, `command`, `prerender`, plus `refresh`/`set`/`withOverride`/`submit().updates()` for single-flight mutations. All are **experimental** on Kit 2.50.2 and in the Kit 3 RC. `query.live` exists but needs Kit 2.59+. Maintainers call remote functions plus async Svelte "our vision for how client-server communication should be handled"; `load` and actions stay supported, not deprecated.
3. **JavaScript baseline**: Vite 7 builds to Baseline Widely Available as of 2025-05-01 (`chrome107, edge107, firefox104, safari16`); Vite 8 moves that to 2026-01-01. Svelte 5's own floor is Chrome/Edge 87, Firefox 83, Safari 14. Anything esbuild can lower to that target is safe; only ES5 output and a short pass-through list (top-level await, newer regex syntax) are off-limits.

**Trident today** (`packages/ui/src/lib/base/helpers`): `mq/mq.svelte.ts` keeps `let _mqBucket = $state(...)` private and exports `_setMqBucket`/`syncMqState`, the docs' function shape. `observe.svelte.ts` and `scroll.svelte.ts` export module singletons (`navigationState`, `scroll`), fine for browser-only state but the SSR-leak shape if anything mutates them during render. `classes`, `rails`, `snippets`, `total` and `persist/persist` `.svelte.ts` files use no runes, so the suffix is unnecessary. Counts: `onMount` 7, `typeof window` guards 17 in 14 files, `svelte/store` 0, `use:` 1, `{@attach}` in 5 files.

**Verdict 1.** Per-instance state: a class with `$state` fields (replaces closures returning getter bags and stores). Singletons: private `$state` in a `.svelte.ts` module behind exported functions, or an exported `$state` object that is only mutated (replaces `writable` singletons). State SSR can touch: `createContext` from a layout (replaces module singletons). `$derived` for derivations, `$effect` for DOM and analytics only, `{@attach}` over `use:`. Rename rune-free `.svelte.ts` to `.ts` when touched.

## 2. Remote functions

Status is as of 2026-09-28. Everything below sits behind `kit.experimental.remoteFunctions` and `compilerOptions.experimental.async`; the docs say the feature "is likely to contain bugs and is subject to change without notice" ([remote functions](https://svelte.dev/docs/kit/remote-functions)), the config page says it "may be changed or removed at any time" ([configuration](https://svelte.dev/docs/kit/configuration)), and the Kit 3 RC keeps it "behind an `experimental` flag as we iron out the last few kinks" ([RC post](https://svelte.dev/blog/sveltekit-3-release-candidate), 2026-08-13).

| Primitive | For | Replaces | Status / version |
| --- | --- | --- | --- |
| `query(fn)` / `query(schema, fn)` | Read dynamic data anywhere; "always _run_ on the server"; identical calls "all point to the same instance"; consume with `await getPosts()` or `.current`/`.loading`/`.error`. ([docs](https://svelte.dev/docs/kit/remote-functions)) | `load` in `+page.server.ts` and `+page.ts`, `fetch` to `+server.ts` ([proposal](https://github.com/sveltejs/kit/discussions/13897)) | Experimental; kit@2.27.0 ([Aug 2025](https://svelte.dev/blog/whats-new-in-svelte-august-2025)) |
| `query.batch(schema, fn)` | Coalesce calls "within the same macrotask" into one request; returns a resolver per input. | n+1 `load`/`fetch` fan-out | Experimental; kit@2.38.0 ([Oct 2025](https://svelte.dev/blog/whats-new-in-svelte-october-2025)) |
| `query.live(fn*)` | "real-time data from the server" from an async generator; async-iterable; `connected` flag and reconnect. | polling in `$effect`, hand-rolled SSE/WebSocket | Experimental; kit@2.59.0, async-iterable and `.run()` removed in 2.61.0 ([Jun 2026](https://svelte.dev/blog/whats-new-in-svelte-june-2026)). **Not on Trident's 2.50.2.** |
| `form(schema, fn)` | Progressive `<form {...createPost}>`, `fields.x.as(...)`, `enhance`, `validate`, `preflight`, `result`, `pending`. | Form actions: "The experimental `form` remote function covers the same use cases as form actions, adding type safety and single-flight mutations" ([form actions](https://svelte.dev/docs/kit/form-actions)) | Experimental; schema/`issues` in kit@2.42.0; `submit` returns boolean in 2.57.0; **enhance callback receives a copy of the form instance, not `{ form, data, submit }`, from 2.61.0** ([Jun 2026](https://svelte.dev/blog/whats-new-in-svelte-june-2026)) |
| `command(schema, fn)` | Mutate "from anywhere (not bound to a form element)"; "cannot be called during render"; no no-JS fallback. | `POST` to `+server.ts` from event handlers | Experimental |
| `prerender(fn, { inputs, dynamic })` | Build-time data; "Queries cannot be used when the entire page is prerendered." | `export const prerender = true` + `load` | Experimental |
| Single-flight: `refresh()`, `set(v)`, `withOverride(fn)`, `submit().updates(...)`, `reconnect()` for live | Refresh or override queries in the mutation's own response so there is no second round-trip; `withOverride` gives optimistic UI. | `invalidateAll()`/`depends()`; manual refetch after actions | Experimental; server `set()` and auto-resolved `refresh()` in kit@2.37.0 ([Oct 2025](https://svelte.dev/blog/whats-new-in-svelte-october-2025)) |

Maintainer intent. The proposal (Simon Holthausen, [kit#13897](https://github.com/sveltejs/kit/discussions/13897), 2025-06-17) lists `load`'s costs ("implicit coupling between what seem like disconnected files", `$types` "clever but somewhat weird solutions") and states "this does not affect `load` functions, they continue to work as is." Rich Harris's async-Svelte proposal ([svelte#15845](https://github.com/sveltejs/svelte/discussions/15845), 2025-04-28) supplies the `await`-in-components half. The RC post says remote functions "make everything else look a bit clunky, including SvelteKit's `load` functions and `actions`". The load doc mentions them only in passing ([load](https://svelte.dev/docs/kit/load)); no deprecation appears anywhere fetched.

**Trident today**: 11 `query`, 2 `query.batch` (`apps/site/src/lib/email/email.remote.ts`, `globe.remote.ts`; the ticket said none), 8 `prerender`, 1 `form` (`contact.remote.ts`, consumed as `submitContactData.enhance(async ({ submit, form }) => ...)` in `apps/site/src/lib/HomePage.svelte`, the signature 2.61.0 changed), 0 `command`, 0 form actions. Five `load` functions remain: three redirects, one `error(404)`, and `apps/app/src/routes/export/print/[token]/+page.server.ts`.

**Verdict 2.** Adopt remote functions as the data layer: `query`/`query.batch` for reads, `prerender` for build-time data, `form` for submissions, `command` for non-form mutations, single-flight `refresh`/`withOverride` instead of `invalidateAll`. Keep `load` for redirects, 404s and per-request gates. Record in #7 that every primitive is experimental, that `query.live` and the 2.61 `enhance` signature need Kit 2.61+, and that the upgrade breaks the one `enhance` call.

## 3. JavaScript baseline

| Fact | Source | Status |
| --- | --- | --- |
| Vite 7 `build.target` default `'baseline-widely-available'` = Baseline Widely Available as of 2025-05-01: `['chrome107', 'edge107', 'firefox104', 'safari16']`; esbuild transpiles and "the build will fail if the code contains features that cannot be safely transpiled by esbuild"; `'esnext'` does "minimal transpiling"; `build.cssTarget` follows it. | [v7.vite.dev build options](https://v7.vite.dev/config/build-options) (v7.3.6) | Stable |
| Vite 8 fixes the date at 2026-01-01: `['chrome111', 'edge111', 'firefox114', 'safari16.4', 'ios16.4']`, via Oxc. | [vite.dev build options](https://vite.dev/config/build-options) (v8.3.1) | Stable; applies with Kit 3 / Vite 8 |
| Baseline Widely Available: "available across browsers for at least 2½ years (30 months)" in Chrome, Edge, Firefox, Safari. | [Baseline](https://web-platform-dx.github.io/baseline/) | Stable |
| SvelteKit sets `target: ssr ? 'node18.13' : undefined`, so the client build uses Vite's default. | [kit/src/exports/vite/index.js](https://raw.githubusercontent.com/sveltejs/kit/main/packages/kit/src/exports/vite/index.js) | Stable (Kit 2 `main`) |
| Svelte 5 itself needs Chrome/Edge 87, Firefox 83, Safari 14, "a Baseline target of 2020"; IE unsupported; `$state.snapshot` needs Chrome 98 / Firefox 94; "This table only covers Svelte itself." Reactivity relies on `Proxy`. | [Browser support](https://svelte.dev/docs/svelte/browser-support), [$state](https://svelte.dev/docs/svelte/$state) | Stable |
| esbuild: "Transforming ES6+ syntax to ES5 is not supported"; always passed through untransformed: regex `s` flag, lookbehind, named groups, unicode property escapes, match indices, set notation; top-level await; arbitrary module namespace identifiers; `import.defer`/`import.source`. | [esbuild content types](https://esbuild.github.io/content-types/) | Stable |

The effective floor is Vite's target, which is newer than Svelte's. Syntax esbuild lowers (optional chaining, `??`, `??=`, class fields, `#private`) is safe to write; APIs such as `Array.prototype.at` and `structuredClone` are in the target browsers; avoid top-level `await` in client modules and regex features newer than the target, which pass through as-is.

**Verdict 3.** Write modern syntax and leave `build.target` at Vite's default (`'esnext'` would drop the safety net). Legacy → modern pairs for this codebase:
