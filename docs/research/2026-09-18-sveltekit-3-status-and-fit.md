SvelteKit 3 status and fit for Trident

Observed September 18, 2026 (UTC timestamps below). Research for Wayfinder ticket [#17](https://github.com/layerdbiz/tridentcubed/issues/17); it implements no migration. Sources are the npm registry (`npm view`), the `sveltejs/kit` and `sveltejs/cli` repositories, and svelte.dev docs and blog. Secondary write-ups were not used.

## Short answer

SvelteKit 3 exists as a **release candidate on the `next` npm tag**, not as a stable release. `@sveltejs/kit@3.0.0-next.27` was published 2026-09-08 and is the current `next`; `latest` is still `2.70.3` (2026-08-18). The team called `next` a release candidate on 2026-08-13 and promised a stable release "in the near future, with no further breaking changes" if the RC holds, with no date. The [3.0 milestone](https://github.com/sveltejs/kit/milestone/7) is 157 closed / 0 open. Remote functions stay behind `experimental.remoteFunctions` in Kit 3 and Svelte's `await` stays behind `compilerOptions.experimental.async` until Svelte 6, so Kit 3 does not stabilize the two features Trident leans on hardest.

Recommendation: **stay on Kit 2 through Milestone 1 (2026-09-26) and adopt Kit 3 immediately after**, targeting the stable tag if it has shipped by then and the RC if not. Evidence and the cost of each path are below.

Two caveats on "no further breaking changes": `next.27` (2026-09-08, after the RC post) still carries three entries labelled `major`/`breaking` ([#16892](https://github.com/sveltejs/kit/pull/16892) single-flight mutation errors, [#16876](https://github.com/sveltejs/kit/pull/16876) remove `Server`/`SSRManifest` from public types, [#16875](https://github.com/sveltejs/kit/pull/16875) adapter `builder.generateManifest` replaced), and [#16990](https://github.com/sveltejs/kit/issues/16990) (opened 2026-09-01, milestone 3.x) asks to restore independent scroll/focus reset controls that `next.13` collapsed into `goto({ reset })`. ## 2. What SvelteKit 3 changes

All items from the [Kit 3 CHANGELOG](https://github.com/sveltejs/kit/blob/version-3/packages/kit/CHANGELOG.md) and the [migration guide](https://github.com/sveltejs/kit/blob/version-3/documentation/docs/60-appendix/35-migrating-to-sveltekit-3.md) unless noted. These are prerelease facts: shipped in `next`, subject to the RC caveat above.

**Minimum versions** (`npm view @sveltejs/kit@next peerDependencies engines`): Node `>=22.17`, `vite ^8.0.12` ("the first Vite 8 release bundling stable `rolldown` 1.0.0"), `svelte ^5.56.4`, `typescript ^6.0.0`, `@sveltejs/vite-plugin-svelte ^7.0.0`. Vite `latest` is 8.3.0 and vite-plugin-svelte `latest` is 7.3.0 today, so the peer set is satisfiable with stable releases.

**Project setup and config**
- `svelte.config.js` is "no longer supported" for Kit; all `kit.*` options and `compilerOptions` are passed to `sveltekit({...})` in `vite.config.js` ([#16873](https://github.com/sveltejs/kit/pull/16873) and guide). The `vitePlugin` option goes away; `vite-plugin-svelte` options such as `inspector` are passed directly. `builder.config.kit` no longer exists for adapters.
- `$lib` becomes `#lib` via `package.json` `imports`; `files.lib` is removed; imports need explicit extensions ([#16360](https://github.com/sveltejs/kit/pull/16360), [#16736](https://github.com/sveltejs/kit/pull/16736)). The `alias` option remains but is deprecated in favour of subpath imports ([configuration docs](https://next.svelte.dev/docs/kit/configuration)); a maintainer confirmed on [discussion #17097](https://github.com/sveltejs/kit/discussions/17097) (2026-09-13) that `alias: { $lib }` still works "to help ease migration although it's deprecated".
- tsconfig extends `$app/tsconfig` instead of `.svelte-kit/tsconfig.json` ([#16458](https://github.com/sveltejs/kit/pull/16458)).
- `$env/static|dynamic/private|public` and `$app/environment` become deprecated aliases for `$app/env`, `$app/env/private`, `$app/env/public` ([#16334](https://github.com/sveltejs/kit/pull/16334)); `$app/stores` is removed; `$service-worker` is removed in favour of `$app/service-worker`, `$app/manifest`, `$app/paths` ([#16450](https://github.com/sveltejs/kit/pull/16450), [#16372](https://github.com/sveltejs/kit/pull/16372)).
- Removed options: `preloadStrategy`, `prerender.origin` (now `paths.origin`), `csrf.checkOrigin` (now `csrf.trustedOrigins`), `experimental.handleRenderingErrors`, `experimental.instrumentation`, `experimental.tracing` (now top-level `tracing`). `version.pollInterval` defaults to one hour ([#16496](https://github.com/sveltejs/kit/pull/16496)).

**Routing and navigation**
- Param matchers move from `src/params/*.ts` to a single `src/params.ts` using `defineParams` from `@sveltejs/kit/params`, accepting functions or Standard Schema ([#16716](https://github.com/sveltejs/kit/pull/16716)). Hyphens allowed in param and matcher names ([#16284](https://github.com/sveltejs/kit/pull/16284)).
- `goto`: `noScroll`/`keepFocus` replaced by `reset` ([#16558](https://github.com/sveltejs/kit/pull/16558)); shallow routing via `goto(..., { shallow: true })`, `pushState`/`replaceState` deprecated ([#16449](https://github.com/sveltejs/kit/pull/16449)); `goto` rejects for URLs that do not resolve to a route; external redirects must be opted in.
- `invalidateAll` deprecated for `refreshAll` ([#16289](https://github.com/sveltejs/kit/pull/16289)); links to the current URL refresh all loads/queries ([#16572](https://github.com/sveltejs/kit/pull/16572)); `preloadCode` takes route IDs ([#16576](https://github.com/sveltejs/kit/pull/16576)); `RouteId` only includes routes with `+page` or `+server` ([#16580](https://github.com/sveltejs/kit/pull/16580)).
- `base`, `assets`, `resolveRoute` removed from `$app/paths`; `page.url` is readonly at the type level ([#16256](https://github.com/sveltejs/kit/pull/16256)).
- Types move out of `@sveltejs/kit` into the module they concern: `Page`, navigation types to `$app/state`/`$app/navigation`, `ActionResult`/`SubmitFunction` to `$app/forms` ([#16694](https://github.com/sveltejs/kit/pull/16694)), hooks types to `@sveltejs/kit/hooks` ([#16737](https://github.com/sveltejs/kit/pull/16737)), env types to `@sveltejs/kit/env` ([#16739](https://github.com/sveltejs/kit/pull/16739)), `RequestEvent`, `Cookies` and remote-function types to `$app/server` ([#16751](https://github.com/sveltejs/kit/pull/16751), [#16764](https://github.com/sveltejs/kit/pull/16764)).
- "Consistent special filename patterns" ([#16382](https://github.com/sveltejs/kit/pull/16382)): any `server` or `remote` segment in a filename or `/server/` directory anywhere in the project (outside `src/routes` and assets) is server-only or remote.

**Remote functions: they do not stabilize.** Migration guide: "Remote functions are still considered experimental — opt in via the `experimental.remoteFunctions` flag alongside `compilerOptions.experimental.async`." Configuration docs: "This feature is not yet stable and may be changed or removed at any time." RC blog: they remain "behind an `experimental` flag as we iron out the last few kinks." Kit 3 changes within the feature: `*.remote.ts` files error unless the flag is on; `event.url`/`event.params`/`event.route` throw inside queries ([#16452](https://github.com/sveltejs/kit/pull/16452), pushback in open issue [#16815](https://github.com/sveltejs/kit/issues/16815)); resource `error` is typed `App.Error | undefined`; `handleValidationError` removed, validation errors go to `handleError` with `kind: 'validation'` ([#16672](https://github.com/sveltejs/kit/pull/16672)); remote form controls must be spread from `form.fields.x.as(...)`, a manual `name=` causes rejection ([#16331](https://github.com/sveltejs/kit/pull/16331)); `validate({ includeUntouched })` renamed to `all`; live-query `.run()` removed; single-flight mutations must be respected by the server ([#16892](https://github.com/sveltejs/kit/pull/16892)); `query.live` sends keep-alive SSE comments. Remote types import from `$app/server`.

**Async compiler flag: still experimental, and that is Svelte's call, not Kit's.** [svelte.dev/docs/svelte/await-expressions](https://svelte.dev/docs/svelte/await-expressions): "This feature is currently experimental, and you must opt in by adding the `experimental.async` option", "The experimental flag will be removed in Svelte 6", and behaviour "is subject to breaking changes outside of a semver major release." Kit 3 only moves where the flag is written (into the Vite plugin options). Svelte `latest` is 5.57.1 today; there is no Svelte 6 tag.

**Adapters and adapter-vercel** ([adapter-vercel CHANGELOG](https://github.com/sveltejs/kit/blob/version-3/packages/adapter-vercel/CHANGELOG.md)): `@sveltejs/adapter-vercel@7.0.0-next.9` (2026-09-08) peers on `@sveltejs/kit ^3.0.0-next.0`; `latest` 6.3.4 peers on Kit `^2.4.0`, so the major bump is mandatory. Breaking in 7: edge runtime and Node 20 runtime removed ([#16520](https://github.com/sveltejs/kit/pull/16520)); edge function build target `es2022`; requires `vite ^8.0.12`; instrumentation API changed ([#16303](https://github.com/sveltejs/kit/pull/16303)). The `runtime` type on `version-3` documents `'nodejs22.x'`, `'nodejs24.x'` etc., so Trident's `runtime: "nodejs22.x"` remains valid. All first-party adapters require Kit 3 and can now contribute Vite plugins (`pre`/`post`, [#16711](https://github.com/sveltejs/kit/pull/16711)).

**`@sveltejs/package`** ([CHANGELOG](https://github.com/sveltejs/kit/blob/version-3/packages/package/CHANGELOG.md)): `3.0.0-next.8` (2026-09-08); `latest` 2.5.8. Breaking: Node 22+ ([#12548](https://github.com/sveltejs/kit/pull/12548)); peers on `typescript ^6.0.0`. New: import aliases are rewritten to relative imports in emitted files ([#16360](https://github.com/sveltejs/kit/pull/16360)), warning for `.server.`/`server/` files that import nothing server-only ([#16266](https://github.com/sveltejs/kit/pull/16266)), Svelte config read via `@sveltejs/load-config` ([#17039](https://github.com/sveltejs/kit/pull/17039)). Package 3 does not itself require Kit 3; it is the Node/TS floor that moves.

**Vite / Rolldown**: Kit 3 requires Vite 8 and uses Vite hook filters and the environment API ([#16134](https://github.com/sveltejs/kit/pull/16134)); page options and remote modules are parsed with Vite's `parseSync` ([#16947](https://github.com/sveltejs/kit/pull/16947)); production sourcemaps supported ([#16412](https://github.com/sveltejs/kit/pull/16412)). This is the same Vite 8 / vite-plugin-svelte 7 move the prior Vite+ research identified; Kit 3 makes it mandatory rather than optional.

**Other breaking removals worth knowing**: `@sveltejs/kit/node/polyfills` removed; `getRequest`/`setResponse` synchronous; `cookie` v2 (ASCII-only names) and cookie `path` defaults to `/`; 204 responses return no body; `error(status, message, {...})` signature; `handleError` receives all errors and can set the status; form action responses use the `fail` status code; `data-sveltekit-*="off"` becomes `false`; `json`/`text` helpers deprecated; `QUERY` HTTP method supported in `+server` ([#16782](https://github.com/sveltejs/kit/pull/16782)).

## 3. Migration path and what Trident would change

**Tooling.** There is a codemod. `sv@next` (`1.0.0-next.7`, 2026-09-04) ships a task-based `sv migrate sveltekit-3` ([cli #1138](https://github.com/sveltejs/cli/pull/1138), [#1241](https://github.com/sveltejs/cli/pull/1241)); the stable `sv@0.17.0` does not have it, and legacy migrations were delegated to `svelte-migrate@1`. Per the [sv migrate docs](https://github.com/sveltejs/cli/blob/main/documentation/docs/20-commands/40-sv-migrate.md) the tasks are `package-json`, `tsconfig`, `svelte-config` (moves supported config into `vite.config.*`), `environment`, `paths`, `external-redirects`, `shallow-routing`, plus a generated `MIGRATION_TASKS.md` checklist for things it cannot rewrite (snapshot [here](https://github.com/sveltejs/cli/blob/main/packages/sv/src/migrate/migrations/sveltekit-3/tests/collect-migration-instructions/MIGRATION_TASKS.snapshot.md)). The guide recommends being on the latest 2.x first for targeted deprecation warnings; Trident is on `^2.50.2`, twenty minor versions behind `2.70.3`.

## 4. Timing risk against Milestone 1 (2026-09-26)

Eight days remain. The migration touches every app's config, the shared UI package's alias/barrel scheme, TypeScript 6, Vite 8, Rolldown, and an RC that received `breaking`-labelled changes on 2026-09-08. None of the Report Generator's Milestone 1 scope requires anything Kit 3 adds; the two features the app depends on most (remote functions, `await` in components) stay experimental in Kit 3 exactly as they are in Kit 2. Doing the move now buys no stability and spends the remaining schedule on toolchain work.

After Milestone 1 the calculus flips. Kit 3 is the only line that will receive new features; `main` is at 2.70.3 and every first-party adapter on `version-3` already peers on Kit 3. The 3.0 milestone is empty and the team has publicly committed to no further breaking changes. The migration itself is mostly codemod-able and Trident uses few of the removed APIs. Waiting for the stable tag is cheap insurance because the RC-to-stable window is unbounded but the team says it is near; if stable has not landed by early October, pinning `3.0.0-next.N` with the `next` adapter and `sv@next` is defensible for a single-team app, provided the `packages/ui` alias behaviour and Storybook are proven first.

Separating the claims:
- Stable facts: version/tag/date data above; Kit 3 peer floors; remote functions and async are experimental in both lines; `sv migrate sveltekit-3` exists only in `sv@next`.
- Prerelease facts: the full change list in section 2 is shipped in `next.27` and documented, but changesets remain in pre mode and post-RC breaking entries exist.
- Plan-only / unverified: any stable date ("near future"); Storybook 10.x behaviour on Kit 3; `svelte-package` 3 alias rewriting versus Trident's generated barrels; TypeScript 6 across `packages/tools`.

## 5. Recommendation

Stay on Kit 2 through Milestone 1, then adopt Kit 3 as the next toolchain task rather than tracking it indefinitely. Concretely: (a) before 2026-09-26, do nothing beyond bumping `@sveltejs/kit` to `^2.70.3` so deprecation warnings point at the exact lines Kit 3 will break, which the migration guide explicitly recommends; (b) after Milestone 1, run `npx sv@next migrate sveltekit-3 --tasks all` on a branch, fold in the Vite 8 / vite-plugin-svelte 7 / TS 6 bump the Vite+ research already scoped, and verify `packages/ui` barrels, the contact form's `.as()` wiring, and Storybook; (c) merge on the stable 3.0.0 tag if it exists by then, otherwise on a pinned `next` with a note to unpin. "Building for the future" is served by moving to the branch all new Kit work lands on; it is not served by doing so in the last week before a milestone, and Kit 3 changes nothing about the experimental status of remote functions or async.
